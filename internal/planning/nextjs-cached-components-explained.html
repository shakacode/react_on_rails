1 Build-Time Transform

The "use cache" directive doesn't run at runtime — the SWC compiler rewrites the function body at build time. Here's what happens to your code:

Source — your code async function ProductCard({ id }: { id: string }) { 'use cache'; cacheTag(`product:${id}`); cacheLife('hours'); const product = await db.products.find(id); return <div>{product.name} — ${product.price}</div>; }
After SWC Transform // The original function body is extracted const $$INNER = async function({ id }) { cacheTag(`product:${id}`); cacheLife('hours'); const product = await db.products.find(id); return <div>{product.name} — ${product.price}</div>; }; // The exported function is replaced with a cache wrapper export var ProductCard = reactCache(function() { return cache( "default", // cache kind "a1b2c3d4e5", // stable SHA-256 of (salt, filename, exportName) 0, // bound args count (closure captures) $$INNER, // the original function [{ id }] // current arguments ); }); registerServerReference(ProductCard, "a1b2c3d4e5", null);
Single Exit Point: Both HIT and MISS return through createFromReadableStream(). This guarantees identical behavior whether the cache is warm or cold, and ensures hydration matches between SSR and client.

6 CacheSignal Coordination

Two different signals, two different jobs. The framework CacheSignal coordinates the two-pass prerender. React's cacheSignal() cleans up in-flight work.

They chain together: Framework CacheSignal fires → abort prospective render → PipeableStream.abort() → React calls request.cacheController.abort(reason) → cacheSignal() fires in every cache() scope → fetch({ signal: cacheSignal() }) cancelled. Clean end-to-end cleanup.
